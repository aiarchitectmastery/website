Choose your next bounded change

Apply the methodology by choosing one reviewable change, making its intent and acceptance criteria explicit, delegating within clear limits and increasing scope only after evidence supports the human decision. A bounded change has one inspectable outcome, not merely a short prompt.

This application overview connects the Core of AI Architect Mastery's AI Driven Development Methodology. It does not require a particular runtime or packaged AAM product.

Updated 2 October 2026 · Source: AAM Methodology v1.1, §§3–4, 6–8 · Owner: AI Architect Mastery

Inspect current behavior before assigning work

Choose an outcome whose current behavior can be inspected, whose constraints are known and whose acceptance can be demonstrated. Confirm that the required context and verification environment are available. If the expected behavior is unknown, clarify it before treating the work as a TASK.

Distinguish the observed baseline from the intended result. Identify what must remain unchanged and what evidence would show a meaningful difference. This is preparation for a bounded assignment, not an additional mandatory Core phase.

Keep the four Core jobs distinct

  1. PRD: define the outcome, scope, constraints, non-goals and acceptance criteria.
  2. PLAN: review dependency order, completion conditions and checkpoints.
  3. TASK: authorize one step with relevant context, permissions and expected evidence.
  4. IMPLEMENTATION: build inside scope, inspect the diff, verify behavior and make the human decision.

Constructed scope decision: one export behavior

"Preserve the current export format while enforcing the approved owner-only rule" is reviewable when ownership and the interface are defined. "Modernize reporting" bundles too many decisions to delegate as one bounded change.

The intended result is not simply a smaller diff. It is a change whose relationship to the requirement and evidence can be inspected.

Do not expand because the agent has spare capacity

Record adjacent findings rather than silently adding them to the assignment. If evidence exposes an invalid assumption, use controlled iteration. More autonomous execution is not progress when the work no longer represents approved intent.

Related concepts

  • Acceptance criteria make the chosen outcome observable.
  • Task handoff turns the bounded change into explicit authorization.
  • Native runtime execution checks whether the environment can produce the evidence.
  • Wider process context keeps optional exploration and release separate from the Core.
