Methodology/Operating Model

DEFINE → DELEGATE → BUILD → VERIFY

DEFINE → DELEGATE → BUILD → VERIFY is AAM's Operating Model: clarify the intended result, authorize bounded work, build within scope and evaluate the result using evidence. These actions describe how the Human Architect directs agent work; they are not four workflow phases.

This is Level 2 of AI Architect Mastery's AI Driven Development Methodology. It is a memorable decision model, not a second workflow. Level 1, the Responsibility Model, establishes accountability; Level 3 makes the Core and its boundary concepts visible: idea → PRD → PLAN → TASK → IMPLEMENTATION → evidence.

Updated 2 October 2026 · Source: AAM Methodology v1.1, §§2–4 · Owner: AI Architect Mastery

How the actions relate to the Core

DEFINE
Establish intent, constraints and acceptance in the PRD; shape a reviewable approach in the PLAN.
DELEGATE
Authorize a TASK with responsibility, selected context, scope, permissions and expected evidence.
BUILD
Execute the bounded assignment within IMPLEMENTATION, recording what changed and what was observed.
VERIFY
Inspect the change and test the claim. A human checkpoint decides whether the result is acceptable or needs further work.

Why this view matters

The action model is a short way to remember the decisions that must not disappear inside an agent session. It does not impose a one-to-one renaming of Core phases: verification and review obligations are already part of IMPLEMENTATION and its acceptance model.

Constructed example: an export boundary

Define that only the record owner may export. Delegate the authorization change with the existing interface preserved. Build the narrow correction. Verify allowed and denied requests, then let the human evaluate whether the evidence satisfies the requirement.

When the result reveals a wrong assumption

VERIFY is not an instruction to keep patching until a test turns green. If the acceptance expectation is missing, return to the appropriate earlier artifact. A passing local test cannot validate an undefined requirement.

Related concepts

  • Acceptance criteria make DEFINE testable.
  • Task handoff makes DELEGATE explicit.
  • Implementation checkpoint turns VERIFY into a human decision.
