TASK: delegate bounded agent work

A TASK is a bounded Work Item for known, defined work, derived from an approved PLAN and assigned with relevant context, scope, acceptance criteria and expected evidence. It gives an agent one reviewable responsibility instead of an open-ended instruction to build a feature.

TASK is the third Core phase of AI Architect Mastery's AI Driven Development Methodology. It connects the approved approach to bounded execution and verification.

Updated 2 October 2026 · Source: AAM Methodology v1.1, §§4.3, 6 · Owner: AI Architect Mastery

Why one responsibility matters

Broad instructions make multi-file or multi-agent work difficult to review. One agent can change a contract while another still assumes the old behavior. A tightly scoped TASK makes the expected contract, permitted change and review boundary visible.

The goal is not simply a smaller prompt. It is enough context that the agent does not have to guess and enough constraint that it cannot quietly expand its own scope.

What a working TASK establishes

  • The applicable approved PLAN step.
  • Relevant files, interfaces, context and constraints.
  • Expected outputs and acceptance criteria.
  • Permitted scope, tools and autonomy boundary.
  • The evidence needed to verify the result and support human review.

Inputs, output and responsibility

Input: one approved plan step and the context needed for it. Output: an authorized, bounded assignment. Owner: the human directs delegation and acceptance; the agent performs the assigned responsibility.

The handoff must make the current assignment explicit rather than relying on conversational memory. A TASK is also one of the sibling Work Types, alongside BUG and PROB; it is not the name for every kind of actionable work.

Constructed TASK: one export correction

Apply the approved owner-only rule to the existing export handler using the established authorization helper. Preserve the public response format. Include owner-success, non-owner-denial and format regression evidence. Stop if the ownership policy or helper cannot support the agreed rule.

When the assignment is insufficient

If relevant context, permitted scope or verification is missing, return the assignment for clarification. A valid PRD and PLAN do not excuse an agent from working against an inadequate TASK. Refresh the handoff before continuing.

Related concepts

  • Work Item is the broader actionable-artifact category.
  • Agent Model separates the assigned responsibility from tools and capabilities.
  • Autonomy boundaries establish when the agent must stop.
  • Task handoff makes authorization and evidence requirements explicit.
